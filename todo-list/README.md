# Todo List

一个用原生 HTML / CSS / JavaScript 实现的待办事项应用：无框架、无构建步骤、无后端。
数据保存在浏览器 localStorage 中，刷新或关闭页面后依然保留。

## 项目简介

这是一个纯前端的小型练习项目，目标是走一遍完整的软件开发流程：先做出能运行的 MVP，
再逐步加入本地持久化和可用性优化，每一步都单独验证，最后整理成可展示的版本。

整个应用由三个文件组成，职责分离：`index.html` 只描述页面结构，`styles.css` 只管视觉，
`app.js` 只操作数据与 DOM。没有使用任何框架、打包工具或第三方依赖，直接打开页面就能运行。

## 功能

- **添加任务**：在输入框输入内容，点击"添加"或直接按 Enter
- **完成 / 取消完成任务**：点任务前面的复选框，或点任务文字（文字与复选框用 label 关联）
- **删除任务**：点任务右侧的"删除"按钮
- **待完成任务数量统计**：实时显示"X 项待完成"
- **localStorage 本地持久化**：增删改都会立即写入本地存储，刷新页面后数据仍在
- **Enter 快捷添加**：输入完按回车即可提交，手不用离开键盘
- **键盘操作**：Tab 依次经过输入框 → 添加按钮 → 复选框 → 删除按钮；空格切换完成状态；
  聚焦删除按钮后按 Enter 可直接删除
- **基本无障碍支持**：复选框和删除按钮带有包含任务内容的 `aria-label`；计数区域使用
  `aria-live` 播报变化；输入框有 `label` 关联；任务文字通过 `label` 与复选框绑定
- **响应式 / 窄屏适配**：320px 宽度下不出现横向滚动，超长任务文字自动换行
- **空状态提示**：列表为空时显示引导文案，而不是空白区域
- **数据容错**：本地数据损坏、格式不正确或存储被浏览器禁用时，页面回退到空列表且不报错

## 技术栈

- HTML5：语义化结构（`form` / `section` / `ul` / `label`）
- CSS3：Flexbox 布局、CSS 变量、媒体查询
- 原生 JavaScript：ES5 语法与 DOM API，不使用任何框架或第三方库
- localStorage：浏览器本地持久化
- Git：版本管理

## 如何运行

纯前端项目，不需要安装依赖，也不需要启动后端。

最简单的方式是用浏览器直接打开 `todo-list/index.html`（双击即可）。

如果更习惯用本地服务器的方式运行：

```bash
cd todo-list
python -m http.server 8000
```

然后访问 `http://localhost:8000`。

## 使用说明

1. 在输入框里输入任务内容
2. 点击"添加"按钮，或直接按 Enter
3. 点击任务前面的复选框，任务被标记为已完成；再点一次可取消完成
4. 点击任务右侧的"删除"按钮删除任务
5. 刷新页面后，任务仍然存在

## 项目特点

- 原生 JavaScript 实现，无第三方框架、无构建工具、无依赖安装
- 数据流单向：事件 → 修改数据 → 局部更新界面。界面状态始终等于数据状态，
  不会出现两者不一致的情况
- 变更时只更新受影响的那一行，不做整表重绘，因此键盘焦点不会被甩掉
- 用户输入通过 `textContent` 写入，不拼接 HTML 字符串，避免注入问题
- localStorage 读写都带容错处理，坏数据不会让页面崩溃
- 支持键盘操作与基础无障碍
- 窄屏适配

## 数据存储

数据保存在 localStorage 的 `todo-list:v1` 键下，值是一个 JSON 数组，每条任务包含四个字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 任务唯一标识 |
| `text` | string | 任务内容（保存前已去除首尾空格） |
| `done` | boolean | 是否已完成 |
| `createdAt` | number | 创建时间戳 |

键名带 `v1` 版本号，便于以后调整数据结构时区分新旧格式。
