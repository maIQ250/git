## 项目一：Todo List 待办清单

**在线体验**：<https://maIQ250.github.io/git/>
（无需登录、无需安装，打开即用）

### 项目简介

一个用原生 HTML / CSS / JavaScript 写的待办事项应用：无框架、无构建步骤、无后端，
数据保存在浏览器 `localStorage` 中，刷新或关闭页面后再打开，任务依然在。

整个应用由三个文件组成，职责分开：`index.html` 只描述页面结构，`styles.css` 只管视觉，
`app.js` 只操作数据与 DOM。

### 解决的问题

想随手记一件事的时候，常见的做法是**装一个 App 或者注册一个账号**——为了记三行字，代价太大。

这个项目解决的就是这一点：**打开一个网页就能用，关掉再打开内容还在，数据只留在本机、不上传任何服务器**。
不做账号、不做云同步、不做协作，把「记一件事」这件事本身做到最省事。

### 主要功能

- **添加任务** —— 输入内容后点"添加"或直接按 Enter
- **完成 / 取消完成任务** —— 点复选框，或点任务文字
- **删除任务** —— 点任务右侧的"删除"按钮
- **待完成数量统计** —— 实时显示"X 项待完成"
- **本地持久化** —— 增删改立即写入 `localStorage`，刷新后数据仍在
- **键盘操作** —— Tab 依次经过输入框 → 添加按钮 → 复选框 → 删除按钮；空格切换完成状态
- **基础无障碍** —— 交互元素带 `aria-label`，计数区域用 `aria-live` 播报变化
- **窄屏适配** —— 320px 宽度下不出现横向滚动
- **空状态提示** —— 列表为空时显示引导文案
- **数据容错** —— 本地数据损坏或存储被禁用时回退到空列表，页面不报错

### 运行方式

纯前端项目，**不需要安装任何依赖**，直接用浏览器打开即可：

```
双击 todo-list/index.html
```

如果更习惯用本地服务器：

```bash
cd todo-list
python -m http.server 8000
```

然后访问 `http://localhost:8000`。

### 自主设计的实用内容

除了增删改查这些基本功能，下面几处是针对**真实使用中容易出问题的地方**专门做的设计：

**1. 局部更新，而不是整表重绘**

很多同类的待办练习在每次操作后都会把整个列表清空重建，直接后果是：
**用键盘操作时焦点会被甩掉** —— 刚按 Tab 聚焦到删除按钮，一按回车，焦点就跳回页面开头了。

这里改成只更新受影响的那一行：增、删、改都只动对应的 DOM 节点，其余部分原样保留。
所以连续用键盘操作时，焦点始终停在该停的地方。这一点有自动化测试守着
（对比操作前后的 DOM 节点是否被重建）。

**2. localStorage 的容错处理**

本地存储里的数据是「用户看得到、改得了、也可能被别的程序弄坏」的。直接 `JSON.parse`
一旦遇到坏数据，整个页面就白屏了。

这里对读到的数据做了完整校验：不是数组、元素不是对象、字段类型不对、缺字段、内容为空……
一共 **11 种异常情况**都有对应的降级处理，最差是回退到空列表，**页面绝不崩溃**。
浏览器的存储被禁用时（比如无痕模式）也一样能正常使用，只是不保存。

**3. 键盘与无障碍不是顺手加的**

- 复选框和删除按钮带 `aria-label`，读屏软件会念出「完成 买牛奶」而不是干巴巴的「复选框」
- 任务文字用 `<label>` 与复选框关联，所以**点文字就能切换完成状态**，不用非得瞄准那个小方块
- 计数区域用 `aria-live`，屏幕阅读器会在数量变化时自动播报
- Tab 顺序按操作习惯排列：输入框 → 添加 → 每条任务的复选框 → 删除按钮

**4. 界面状态只有一个来源**

界面永远是数据的投影：所有操作都是**先改数据、再从数据渲染**，
不会出现「界面显示已完成、数据里还是未完成」这种两边对不上的情况。

## 项目二：校园失物招领系统

### 项目简介

一个校园失物招领平台，按"**失物招领柜**"的模型设计：**管理员把收到的实物登记进系统**
（拍照、拾获地点、拾获日期），**学生打开页面就能看到柜子里现在放着什么**，搜索后打开详情查看领取方式。

- 服务端：Node.js 24 内置模块手写 HTTP 服务，不引入 Express 等框架
- 数据库：Node.js 24 内置的 `node:sqlite`，单文件数据库
- 前端：原生 HTML / CSS / JavaScript，与 todo-list 风格保持一致
- 第三方依赖：**零**。`package.json` 里没有 `dependencies`

### 当前实现情况

**已实现（可以真实操作）**

| 模块 | 说明 |
| --- | --- |
| 账号体系 | 学生注册 / 登录、管理员登录、退出、会话保持（7 天） |
| 密码安全 | `scrypt` 加盐哈希存储，校验用 `timingSafeEqual` |
| 角色权限 | 学生不能进入管理端；管理员和学生使用不同的登录入口 |
| 物品登记 | 管理员登记物品，支持上传一张照片（JPEG / PNG / WebP，≤2MB，校验文件头魔数） |
| 失物招领柜 | 学生登录后看到在柜物品列表，带缩略图、类型徽章、状态徽章 |
| 搜索 | 关键词模糊匹配标题 / 描述 / 地点，转义 `%` `_` 保证按普通字符处理 |
| 筛选与分页 | 按类型（招领 / 寻物）和状态（在柜 / 已归还 / 全部）筛选，分页浏览 |
| 物品详情 | 大图 + 完整描述 + 登记人 + 领取方式（未登录时联系方式不可见） |
| 图片存储 | 图片以 BLOB 存进数据库，不写磁盘；通过独立接口按需返回 |
| 修改与删除 | 作者本人或管理员可以修改、删除自己的条目 |
| 我的登记 | 管理员查看自己登记过的物品列表 |

**尚未实现（界面上是占位，或完全没有入口）**

- **认领申请闭环** —— 学生提交认领申请、管理员同意 / 拒绝、标记已归还
- **管理员审核寻物启事** —— 管理页的"待审核队列"目前是占位卡片
- **用户管理** —— 查看 / 封禁学生账号
- **数据统计** —— 管理页和学生页顶部的统计数字目前都显示"—"
- **学生发布寻物启事的界面** —— 后端 `POST /api/items` 接口支持学生发布（发出去是"待审核"状态），
  但学生端页面上**还没有发布表单**，目前只能通过接口调用

设计文档和分阶段计划在 `lost-found/docs/` 下，写清了每个阶段做了什么、还剩什么。

### 运行方式

需要 **Node.js 24 或更高版本**（用到了内置的 `node:sqlite`）。不需要安装任何依赖。

**方式一：双击启动**

```
双击 lost-found/start.bat
```

**方式二：命令行**

```bash
cd lost-found
node server.js
```

启动后浏览器访问 **http://localhost:3000** 。
关闭窗口即停止服务。端口可以用环境变量 `PORT` 覆盖。

这个文件已被 `.gitignore` 忽略，不会提交到仓库；删掉它再启动就会重新初始化。

## Git 与 GitHub 使用说明

**仓库地址**：`git@github.com:maIQ250/git.git`

**提交历史**：按功能分阶段提交，每个提交只做一件事，提交信息采用 `类型(范围): 说明` 的格式，
例如 `feat(lost-found): add item search, filtering and pagination`。

**分支用法**：

- `main` —— 主分支，保持可用状态
- 开发新功能时从 `main` 拉出 `codex/功能名` 分支，做完后合并回 `main`

**克隆并运行**：

```bash
# 克隆仓库
git clone git@github.com:maIQ250/git.git
cd git

# 运行 todo-list：直接双击 todo-list/index.html

# 运行 lost-found
cd lost-found
node server.js
```

**日常提交**：

```bash
git add <具体文件>        # 只暂存要提交的文件，避免夹带无关内容
git commit -m "feat: 说明这次做了什么"
git push
```
